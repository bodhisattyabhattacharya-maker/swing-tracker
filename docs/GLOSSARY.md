# Glossary

Shared vocabulary. Cheap file; it stops two people building two meanings for one word.

| Term | Means here |
|---|---|
| **Parameter** | One tracked number, computed on a schedule. Not a signal. The catalogue in `web/lib/columns.ts` holds 51; 22 read live data and the rest are `planned`. |
| **Norm** | A threshold we define on a parameter that decides whether a cell gets coloured. Our judgment, stated explicitly. |
| **Rule** (Phase 2) | A named condition over one or more parameters that we want to be alerted on. |
| **Signal** | One firing of a rule on one ticker on one date. |
| **Episode** | A deduplicated run of consecutive signals. A rule firing 60 days straight is ~1 episode, not 60 — use episodes when judging sample size. |
| **Clock** | A refresh schedule. v1 runs **one** — after the close on weekdays — plus a separate rebuild. Hourly, SEC-check and weekly clocks arrive with the parameters that need them. |
| **Baseline** | Buying any watchlist name on any random day over the test window. The bar a backtest must beat. |
| **Edge** | A rule's average forward return minus the baseline's, at the same horizon. |
| **Owner / viewer** | ~~Two roles enforced by RLS.~~ **Not in v1** — the dashboard is open with no login and has no user-initiated actions, so there is nothing to authorise (PROPOSAL §4). Kept because Phase 2 may reintroduce it; if it does, that is the reason to add identity, not the other way round. |
| **Completed week** | The last fully-closed weekly bar. All weekly parameters read this, never the current partial week. |
| **Warm-up floor** | The minimum bars before a recursive indicator stops reflecting its seed value. Below it, suppress the number rather than showing it. Floors are listed in `DEFINITIONS.md` §4 — **not** `CONSTRAINTS.md`, which is about the outside world. |
| **Golden value** | A known-correct figure for a specific ticker and date, committed as a test fixture. Catches the 'plausible but wrong' errors that invariant checks miss. |
| **Provider interface** | The contract every data source implements, so a paid feed can replace a free one without touching parameters, rules or the dashboard. |
| **Theme** | A ticker's peer group in `watchlist.yml`. Sector-relative ranks are computed within a theme, so a theme needs several members to mean anything. |
| **Hard stop** | An action requiring in-session confirmation every time — deploy, migration, external message, anything irreversible. Backed by `.claude/settings.json`, not just by asking. |
| **Tag** | A ticker's granular label in `watchlist.yml`, for display and filtering only. Never used in a calculation — that is what `theme` is for. |
| **Feature** | A stored column derived from bars — what a parameter is made of, or is. `daily_features` is the daily set. "Parameter" is the user-facing number on the grid; "feature" is the column it comes from, and for most of them they are the same thing. |
| **Seed-decay flag** | A boolean beside a recursive indicator (`rsi_daily_seed_ok`) saying whether it has cleared its warm-up floor. False means computed-but-still-partly-its-seed: show it if you must, never colour a cell on it. |
| **Invariant check** | A check phrased as "count the rows that violate this", so the expected answer is always zero. Preferred to checking an average, where a new violation can hide. |
| **MISSING** | A verify-script status distinct from both PASS and FAIL: the row the check needed does not exist, so nothing was verified. Never treat it as a pass — see `INCIDENTS.md` for why this project is blunt about it. |
| **NOPAT** | Net operating profit after tax — `OperatingIncomeLoss × (1 − effective tax rate)`. The numerator of our ROIC. Deliberately operating income, not net income, so capital structure and one-off items stay out of a return-on-capital number. |
| **Invested capital** | Ours is `total debt + total equity − cash`. There are at least five accepted definitions; this is the recognisable one and the column says so. ROIC is definition-sensitive and comparing ours to a vendor's is comparing two different measures. |
| **Cover-page shares** | `dei:EntityCommonStockSharesOutstanding` — the share count on a filing's cover, as of the filing date. A point-in-time count, unlike the basic and diluted weighted averages, which are averages over a period built for EPS and smear a buyback across the quarter it happened in. |
| **Searched column** | A parameter collected by web search rather than computed from a feed — analyst target gap, forward P/E, PEG. Carries its own value, source and date, and is never mixed into the SEC-derived fundamentals: one is measured, the other is someone's opinion. Usable as a rule filter, never a trigger, and not backtestable. |
| **As-reported** | The figure as it was filed, not as later restated. Using restated numbers would let a backtest standing in 2025 see a 2026 correction, which is the point-in-time property hard constraint 4 buys and decision 0002 protects. |
| **Fund** | An ETF on the watchlist. `tickers.is_fund`. Trades, charts and oscillates like a stock, so every price parameter applies; has no income statement, so every fundamental is **not-applicable** rather than missing. Distinct from **index** — a fund is a grid row, an index never is. |
| **Index** | A context series (^VIX, ^VIX3M, ^GSPC). `tickers.is_index`. Never a grid row, never ranked, never in breadth; it exists to be the thing other numbers are measured against. |
| **MA stack** | The ordering of close, EMA21, SMA50 and SMA200 as one categorical chip: Full bull, Full bear or Mixed. A shape, not a score — it says how the averages are arranged, never what to do about it. |
| **Tone** | A signal chip's colour class — bull, bear or neutral — derived from its LABEL. Deliberately not a norm verdict: a verdict comes from a threshold in `config/norms.yml` and a tone comes from the category, so editing a norm can never restyle a chip. |
| **Bars since** | Trading bars elapsed since an event, 0 on the event's own bar. Never calendar days — a calendar gap spans a different number of sessions depending on where the weekends fall (decision 0035). Null means the event is not in the history we hold. |
| **Cell state** | Which of eight sentences a cell is making: `na`, `planned`, `null`, `warmup`, `no-norm`, `below`, `above`, `normal`. Tested in that order, and the order is the contract — decision 0043. |
| **Preset** | A named subset of the column catalogue (Momentum, Technicals, Value, All). Changes which columns are visible and nothing else — not a filter on rows, and not a different view of the data. |
| **Planned column** | A parameter that is designed and not built. Marked `planned` under its column heading, with dashes in its cells. The marker is on the column, not on each cell, because the fact is about the column: nobody has that number, so it is not "no value for this name". |
| **Not applicable** | A question this security cannot be asked — a fund has no P/E, an unrankable theme has no peer group to rank within. Marked `n·a` in the cell, because unlike `planned` it varies row by row. Intentional, and never the same as missing. |
| **Pure module** | A file in `web/lib` with no fetch, no environment access and no secret, and therefore safe for a client component to import. Enforced, not documented — `scripts/ci/check_web_boundary.sh` rule 2. |
| **Client boundary** | The line between `lib/grid.ts`, which holds the service_role key and is server-only, and everything the browser bundle may contain. Data crosses it as props; the module that can fetch data does not cross. |
| **Scrim** | The darkening at the right edge of the table's scroller, on only while there is content past that edge. A darkening rather than a colour, because what lies under it varies — band row, tinted cell or pinned cell. |
| **Deferred symbol** | A symbol a run planned to fetch and did not, because the run hit its per-symbol cap or a rate limit. Recorded in `ingest_runs.detail.daily.deferred`. Legitimate for one run; a symbol deferred every run is being starved, which is what happened on 2026-09-18. |
| **Priced today** | How many tracked symbols have a bar on `data_through`. Different from how many we track: a symbol can be tracked, have years of history, and still be missing from the newest date. `grid_status.symbols_priced`. |
| **Per-run cap** | The maximum symbols one ingest run may fetch, from the edge function's 150 s wall clock rather than from any rate limit. It cuts an alphabetical tail rather than a sample, so it must exceed the universe — a test enforces that against `config/watchlist.yml`. |
| **Chart theme** | The resolved palette, read off the document at runtime by `web/lib/chart-theme.ts`. Canvas cannot resolve a CSS custom property, so colours must be handed to the charting library as literals — reading them from the page is what stops that becoming a second palette. |
| **Regime strip** | The colour bar under the VIX chart: one mark per session, coloured by which side of the VIX norm band that session closed on. Carries no y-axis, because the meaning is entirely in the colour. |
| **Session gap** | A date with no value for an index series, because FRED publishes later than the equities. Charts skip it; they never bridge it or zero-fill it, since either would draw a day that did not happen. |
| **Cell history** | The full stored series for one parameter on one security, read from `grid_cells` or `rs_cells` filtered by symbol **and** param. Both filters are mandatory: either alone is a different query plan. |
| **Allowlist route** | One of the two endpoints that read the database on demand — `/api/cell-history` and `/api/stock-history`. It validates `symbol` and `param` against a list derived from `COLUMNS` before either reaches a query, because the repo is public and the key is full-access. |
| **Strip** | The Deep Dive layout: one fixed-width analysis column per security, scrolled sideways. Fixed width and equal height are the whole point — a section sits at the same y on every name, so the eye can travel horizontally and read one thing across the watchlist. A column that sized itself to its content would end that silently. |
| **Section render** | What one strip section puts on screen for one security: `data`, a *not-applicable* sentence, or a *blocked* sentence. Derived, never declared, and `na` is tested before `blocked` — an ETF's Fundamentals panel is permanently inapplicable, not waiting for a vendor. |
| **Blocked section** | A section whose params are all `planned`. Carries one short sentence naming the actual blocker, capped at 120 characters — it renders once per column, so a paragraph there is a paragraph per security. The reasoning goes in the page footnote, once. |
| **Mark** | Whether the price panel draws candles or a line. Decided by **pixels per bar**, not by a bar count: candles while each gets at least 5px, a line once they do not. At a 390px plot that switch lands at 78 bars. |
| **Range** | The price panel's view length — 3M/1Y/5Y on daily, 1Y/3Y/5Y on weekly. Buttons rather than panning, because panning moves the window without widening it, so the line mark could never be reached (decision 0050). One request serves all three. |
| **Lazy panel** | A section that reads its own data when the column is scrolled to, rather than in the page payload. Only the price panel is one: 53 names of daily bars is far more than a payload can carry, and a column you never reach costs nothing. |
| **Reachability check** | A CI check that enumerates what can actually happen and fails on anything declared but unproducible — and, since 0050, on anything producible only in the arithmetic and not through a control a reader has. Written after the third time something was styled and documented while being impossible to reach. |
| **Verdict scale** | The ordinary red/green pair: red is below the norm band, green is above, and that is a statement about a relationship, not a recommendation. It is the scale every security metric and the term-structure tile are read on. Since 0052; it was blue and ochre before. |
| **Intensity scale** | The second, deliberately separate pair — slate for calm, amber for stressed — used by the VIX tile and the regime strip and nothing else. VIX exists on it because its band is 16–30, so on the verdict scale a calm tape would paint red and a stressed one green. A market tile declares which scale it is on; the alternative, inverting VIX inside the verdict scale, was rejected as the kind of exception that stops a palette meaning anything. |
| **Overlay colour** | `--ma1/--ma2/--ma3`, the three moving-average line hues. Kept off the verdict pair on purpose: an average is a reference line, and a 50-day average drawn in the colour that means "below its norm" everywhere else is a claim the chart is not making. |
| **Group rail** | The coloured 3px rule along the top of a category heading, one hue per group. What makes a 51-column table navigable — the eye finds a band by colour and position long before it can read nine small-caps labels. Forward Look's rail is grey because that band is permanently planned. |
| **Theme mode** | Which of three positions the colour control is in: `system`, `light` or `dark`. Held on the root element as `data-mode`, alongside `data-theme` which is what the stylesheet keys off and which `system` deliberately leaves unset. Both are written before first paint; from an effect they would flash the wrong palette on every navigation. |
| **Contrast floor** | 4.5:1, the WCAG AA bar for normal text, applied to every foreground/background pairing the stylesheet can produce in both themes. Normal and not the 3:1 large-text allowance, because these labels run 9–13px. Enforced by `scripts/ci/check_contrast.sh`, which is also what found `--ink-faint` sitting under 3:1 since the first palette. |
| **Band** | One of the ten category groups in the header's top row — Price, Technicals · daily, Technicals · weekly, MA signals, Relative, Revenue, Profit, Valuation, Quality, Forward look. `GROUPS` in `lib/columns.ts` is the order, for every preset: `columnsFor` sorts by it and then by declaration order, so a preset cannot carry a second order of its own. Ten since 0053; the standalone RSI band was retired into the two technicals bands. |
| **Render kind** | How a column's value is drawn: `number`, `chip`, `sparkline` or `rank`. Each reads a DIFFERENT field of `CellLike`, which is why "is this cell empty" is a different question for each one. `number` is the fall-through in both renderers; every other kind must have an explicit branch in both, and `scripts/ci/check_render_kinds.sh` fails otherwise — a kind with no branch renders as a plausible-looking number in silence. |
| **Trace** | The eight-quarter sparkline. Bars, neutral ink always, newest quarter marked by weight rather than hue, baseline at zero rather than at the series minimum, and a quarter the company did not report drawn as nothing at all — its slot is reserved so the cadence stays even, but a hole is not a zero. Geometry in `lib/sparkline.ts`, shared by the grid and the strip so the two cannot disagree. |
| **Reachable render kind** | One that some column carries AND at least one of those columns is `live`. Both renderers test `planned` before the render kind, so a kind whose every column is planned cannot appear on screen however well it is implemented. `sparkline` and `rank` are both unreachable until Stage F, which the check prints on every run rather than leaving to a comment. |
| **Tile descriptor** | The line under a market tile's value saying what the number is in three or four words — `IN BAND`, `CONTANGO`, `ABOVE OWN SMA200`. For a tile with a norm it names which side of it the value fell on, so the tile reads without decoding the colour; for one without, it says what the number measures. Reserved even when empty, because a line that appears on one tile and not another makes that tile taller than the rest. |
| **Band noun** | Whether a theme band calls its members stocks, funds or names. Measured from the rows, not assumed: every theme holds companies except ETFs, which holds ten funds, and that is the band where the spec's blanket "STOCKS" would have been most visibly wrong. |
| **Regime band** | One of the five VIX states: calm, normal, high, stress, extreme. `REGIME_BANDS` in `lib/market-history.ts` is the scale. It tiles the number line — every VIX value belongs to exactly one band — and `scripts/ci/check_regime_scale.sh` enforces that, including that exactly one band owns each shared edge. |
| **Edge ownership** | Which of two adjacent bands claims the value exactly on their shared boundary, as the explicit `loInclusive`/`hiInclusive` fields rather than as a consequence of list order. It is deliberately **not uniform**: the norm is a closed interval, so `normal` owns both 16 and 30 while every band outside it owns only its upper edge. Any single rounding rule gets one of the two wrong — and before this was written down, `regimeOf(16)` said `calm` while the VIX tile said the same session was inside the band. |
| **Display cut** | A boundary on the regime scale that no verdict reads: 50 and 80, in `REGIME_CUTS`. They exist so the chart can describe a crisis. Distinct from a **norm** (16 and 30, from `config/norms.yml`, CI-pinned, colours the VIX tile), and drawn differently on purpose — a norm is a dashed line with an axis label, a display cut is only a change of tint. |
| **Band tint** | The 8.5% wash behind the VIX line marking which regime a price level falls in. HTML positioned over the canvas, not a chart primitive: Lightweight Charts has no horizontal band, a filled series would show up in the crosshair readout as a hoverable value, and a thick price line cannot carry a label. |
| **Fill token** | A colour carried on a custom property (`--band-ink`) rather than on `color`, because it is only ever a swatch or a wash and never text. Declaring one as `color` tells `check_contrast.sh` it is text and it is measured against the 4.5:1 floor — correctly, and for the wrong question. Saying what it is costs nothing and keeps the floor strict for everything that really is text. |
